# AI workflow / журнал промптов

Этот файл фиксирует примерный процесс, который можно честно использовать как шаблон документации проекта. Если вы повторно генерируете или меняете части проекта с помощью другой модели, добавьте фактические промпты, инструмент, дату и результат.

## 1. Бриф и структура

**Промпт**

> Ты — senior landing-page designer и frontend developer. Предложи структуру адаптивного маркетингового лендинга для концепта Битрикс24. Цель: объяснить ценность единого рабочего пространства для небольшой и средней команды и привести пользователя к интерактивному квизу. Нужны hero, преимущества, сценарий работы, квиз на 3 вопроса и форма заявки. Не утверждай, что страница официальная; все маркетинговые формулировки должны быть концептуальными, без выдуманных цифр и неподтверждённых обещаний.

**Что проверять вручную**

- Есть ли понятная аудитория и одна главная цель.
- Не появились ли неподтверждённые статистические данные.
- Логично ли ведёт пользовательский путь к квизу и форме.

## 2. Визуальная система

**Промпт**

> Создай визуальную концепцию SaaS-лендинга: светлый фон, выразительная типографика, фиолетовый акцент, мягкие градиенты, аккуратные карточки, UI-мокап рабочего пространства. Не копируй существующий сайт пиксель-в-пиксель. Задай дизайн-токены для цветов, радиусов, отступов и состояний hover/focus. Интерфейс должен быть адаптивным и читабельным на мобильных устройствах.

**Что проверять вручную**

- Контраст текста и фона.
- Единообразие отступов, радиусов и заголовков.
- Переполнение мокапа и карточек на узком экране.

## 3. Разработка интерфейса

**Промпт**

> Реализуй лендинг на чистом HTML, CSS и vanilla JavaScript без сборщика и сторонних JS-библиотек. Используй семантические секции, понятные классы, адаптивные CSS media queries, состояния focus и prefers-reduced-motion. Добавь квиз на 3 шага с валидацией выбора, персональную рекомендацию на основе ответа и демонстрационную форму без сетевой отправки. Не добавляй фиктивную отправку на реальный сервер.

**Что проверять вручную**

- Нет ли ошибок в консоли.
- Работают ли кнопки назад/далее и повторное прохождение квиза.
- Не отправляются ли данные формы в сеть.
- Работает ли клавиатурная навигация.

## 4. Проверка и доработка

**Промпт**

> Проведи ревью HTML/CSS/JS как frontend code reviewer. Ищи проблемы адаптивности, семантики, доступности, ошибок состояния, вводящих в заблуждение сообщений и неработающих ссылок. Сначала перечисли конкретные проблемы с файлами и участками кода, затем предложи минимальные исправления. Не переписывай всё без необходимости и не заявляй, что тесты пройдены, если их фактически не запускал.

**Чек-лист фактической ручной проверки**

- [ ] Ширина 1440 px — desktop.
- [ ] Ширина 768 px — tablet.
- [ ] Ширина 390 px — mobile.
- [ ] Квиз не идёт дальше без выбранного ответа.
- [ ] Рекомендация появляется после третьего ответа.
- [ ] Кнопка «Пройти ещё раз» сбрасывает квиз.
- [ ] Форма требует имя и контакт.
- [ ] Форма показывает демонстрационное подтверждение и не отправляет данные.
- [ ] Мобильное меню открывается и закрывается.
- [ ] Проверены ошибки в DevTools Console.

## 5. Пример формулировки для собеседования

> Использовал AI как инструмент ускорения: для проработки структуры, вариантов интерфейса, генерации и ревью кода. Затем вручную проверял разметку, адаптивные состояния, логику квиза, валидацию формы и соответствие результата брифу. Форма демонстрационная и не передаёт пользовательские данные на сервер.

Не указывайте проверку как выполненную, пока действительно не пройдёте чек-лист в браузере.
